# 字节跳动校招规则

规则入口：`parser.ts`，标识 `bytedance@1.0.0`。对应正式扩展 `0.3.4`。

## 路由与职责

- 归属站点：`https://jobs.bytedance.com`。
- 已验证页面：`/campus/resume/<数字 ID>/apply`，查询参数不参与匹配。
- 后端根据区块标题、字段标题、控件类型及字段模板锚点，生成当前页面字段 ID 与简历来源的绑定；不执行浏览器动作。
- 同站未知路径、未知字段、结构变化、缺少等价选项均返回不支持或待处理，**不会调用 AI 兜底**。其他站点仍沿用现有路由策略。
- 前端继续使用通用扫描器、经历操作和执行器。Universe UI 单选控件驱动仅处理 DOM 交互，不含字节域名、简历字段或业务别名。

## 已保存的映射

| 区块 | 数据来源 | 范围 |
| --- | --- | --- |
| 基本信息 | `profile` | 姓名、手机号码文本框、邮箱；排除同名的电话区号下拉框 |
| 教育经历 | `education.fields/extra` | 学校、学历、专业、起止时间；学历类型、学院、实验室、领域方向、导师 |
| 实习经历 | `experience.fields` | 公司、职位、描述、起止时间；仅明确属于实习的记录 |
| 工作经历 | `experience.fields` | 同上；仅明确属于正式/全职/兼职的记录；本轮真实页面此区块未展开，未验收实际填写 |
| 项目经历 | `project.fields` | 名称、角色、链接、描述、起止时间 |
| 语言能力 | `language.fields` | 语言、精通程度；不把考试证书或分数推断成会话能力 |
| 自我评价 | `profile.selfIntroduction` | 单个文本控件 |

经历类型优先使用 `extra.employmentType`；缺失时才使用明确的 `extra.profileSection`。未知的显式类型不被旧区块信息覆盖，不凭职位名称猜类型。先筛选来源记录，再分配目标索引。

学历别名和学历类型别名集中在同一规则文件。选项只允许唯一、可用的精确/已声明别名匹配。比如“硕士研究生 → 硕士”“全日制 → 统招全日制”。“非全日制”不等同于“统招非全日制”，未证明等价时留待处理。

## 维护与验收

1. 在真实页面确认标题、控件和选项，调整本目录规则；不要向通用扫描器添加业务字段匹配。
2. 增加 `apps/api/tests/bytedance-rules.test.mjs` 回归，覆盖未知结构拒绝、记录筛选、当前字段 ID、选项歧义及 AI 零调用。
3. 构建 API 与扩展的受影响模块，再从扩展正式按钮执行真实页面测试；独立回读和视觉检查属于开发验收。
4. 分别报告实际改写正确率、可填字段覆盖率和整页缺口。不要把“所有已映射字段正确”写成“整份简历完整”。
