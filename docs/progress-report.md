# 领客项目阶段进度汇报

更新时间：2026-09-20

## 一、整体进度

目前已完成领客求职助手的基础产品框架和核心后端能力建设，形成了“营销主页 + 工作台 + 用户系统 + 个人资料 + 投递航迹 + 智能填写”的整体结构。

当前项目已经具备本地联调条件：

- Next.js 前端开发服务：`http://localhost:3000`
- API 后端开发服务：`http://localhost:3101`
- PostgreSQL 和 Redis：Docker 本地运行
- Prisma 数据库迁移已接入
- 用户注册、登录和工作台权限保护已接通

## 二、已完成内容

### 1. 产品页面和应用结构

- 完成领客营销主页。
- 完成工作台统一页面壳和左侧导航。
- 完成三个子功能页面结构：
  - 个人资料

  - 投递航迹

- 完成腾讯蓝白视觉体系、工作台布局和响应式基础适配。

- 完成邮箱 + 密码注册和登录。

### 3. 个人资料功能

已完成个人简历的结构化管理，主要包括：

- 基本信息
- 求职意向
- 教育经历
- 工作/实习经历
- 在校经历
- 项目经历
- 获奖经历
- 论文与专利
- 技能
- 语言能力
- 证书信息

支持资料分区编辑、保存、软删除、恢复和用户数据隔离。

#### AI 简历解析方案

当前采用：

```text
PDF / DOCX 简历
  ↓
百度高精度 OCR
  ↓
DeepSeek 文本模型解析和结构化
  ↓
字段标准化和数据库字段映射
  ↓
写入用户简历资料
```

解析结果会根据数据库结构进行标准化，教育、项目、奖项等可重复内容会拆分为独立记录。发生字段冲突时，支持保留原内容或覆盖已有资料。

### 4. 投递航迹

投递航迹已经完成主仓接入，包含：

- 投递记录创建、查询和更新。
- 投递状态管理：待投递、已投递、筛选中、笔试/面试、Offer、已结束。
- 投递事件记录。
- 面试、测评和后续跟进任务。
- 投递记录日历数据接口。
- 投递记录幂等处理和版本控制。
- 用户维度的数据隔离。
- 邮箱登录和邮件相关能力接入。
- 邮件解析并自动识别投递状态和职位信息。

#### 邮件解析方案

邮件解析使用 Gemini 2.5 Flash-Lite，流程为：

```text
邮箱消息
  ↓
邮件内容提取
  ↓
Gemini 2.5 Flash-Lite 解析职位和状态
  ↓
匹配已有投递记录
  ↓
更新投递状态、事件和跟进任务
```

### 5. 智能填写

已完成智能填写 Demo 与主仓 API 的接入基础：

- 浏览器插件读取招聘页面字段。
- 通过简历读取 API 获取结构化资料。
- 支持统一 AI 网关调用。
- 支持便宜模型重试，最后切换官方模型。
- 已优化填写流程，当前整体填写速度控制在 1 分钟以内。
- 已支持用户资料版本号，用于缓存失效和资料更新判断。
- 已建立页面字段和结构化简历的分离契约。

当前速度仍未达到“求职方舟”的水平，后续还需要继续优化页面字段识别、请求合并和填写执行阶段。

## 三、当前进行中

目前正在实现规则库能力，用于：

### 职位列表推荐

计划增加职位列表和个性化推荐能力，第一阶段使用 GitHub 上公开维护的校招信息聚合页作为外部数据源：

- [xixicc2027：2027 届秋招信息聚合](https://github.com/xixicc186/xixicc2027)：提供按行业、岗位方向、地点和截止时间整理的招聘信息，并维护可供程序读取的 `jobs.json`。
- [Campus2027：2027 届互联网校招与 2026 届实习信息汇总](https://github.com/namewyf/Campus2027)：提供按招聘批次、公司、地点和官方投递入口整理的校招与实习信息。

接入时会将外部数据先转换为领客内部的职位数据格式，保留来源仓库、原始链接、更新时间和数据抓取时间。职位列表支持按职位、公司、地点、招聘批次和截止时间筛选，并结合用户的求职意向、技能和结构化简历做推荐排序。外部聚合内容只作为职位发现入口，投递时仍跳转到原始官方链接；数据同步、重复职位去重、过期标记和来源变更记录会由后台定时任务处理。
