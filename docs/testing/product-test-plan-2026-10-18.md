## 执行约束

先同步已有功能，再冻结产品源码。只修改测试文档、测试脚本与忽略的测试证据；发现 Bug 记录复现，不在测试过程中修复。使用隔离测试环境、合成账号/资料，招聘页面只填写、不提交。

结果分为：通过、失败、阻塞、未测。单元测试、HTTP 集成和真实浏览器分别标注；某一层通过不能替代端到端通过。每项记录实际操作、预期、实际、证据和耗时；历史测试仅作参考。

## 环境和数据

- 远端网页：`https://linkaigo.com/autofill-test`，API 同路径 `/api`；本地隔离 PostgreSQL 用于涉及注册、角色和跨账号的可重复集成测试。
- Chrome 当前网站下载扩展 `jmfbkpdfefifliffkdkmljihmkeapjkb` v0.3.0；不开旧开发扩展。
- 使用既有合成测试账号，其完整简历有 18 条经历。远端新增业务数据带 `QA-20261018` 标记；不接触其他账号记录。
- 测试头像使用公开测试图片；导入内容为新建合成文本，不使用私人简历。登录凭据和 Cookie 只在内存/忽略目录。
- 固定提交、容器版本、模型配置存在性和时间；接口设置超时，单个第三方流程限时，不无限重试。

## 执行顺序

1. 固定部署与数据基线，保存 PRD/计划；确认无待发布产品修改。
2. 运行已有自动化与隔离数据库集成；执行远端认证/资料/投递/导出/填写服务用例。
3. Chrome 覆盖官网、账号入口、资料编辑、主页头像、投递/日历/邮件、教程与扩展。
4. 独立招聘页真实点击填写并计时；不调用内部 runner 代替真实入口；保存结束截图和可核验结果。
5. 对缺陷做一次有界复现，区分部署、产品、第三方和配置问题。
6. 汇总功能表、Bug 清单、阻塞项和性能基线；复核没有改产品源码，将文档和测试脚本推送 GitHub 与远端测试目录。

## 验收门槛

账号/数据隔离不能失败；主流程必须给出可理解反馈。注册、导入或填写被代理/配置阻断，相关功能不得标记端到端通过。扩展 partial 或超过预算如实记失败项；无法完成全字段视觉分母时不虚报准确率/召回率。测试最终产物为一张功能结果总表和有证据的缺陷列表，本轮不修复。
