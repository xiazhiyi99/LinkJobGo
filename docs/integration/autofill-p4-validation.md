## Docker 复现入口

在仓库根目录运行，Docker 构建不使用真实环境配置：

```bash
docker build -f apps/api/Dockerfile -t lingke-api:p4-test .
docker build -f apps/web/Dockerfile \
  --build-arg NEXT_PUBLIC_API_URL=http://127.0.0.1:3001 \
  --build-arg NEXT_PUBLIC_CAPTCHA_PROVIDER=disabled \
  -t lingke-web:p4-test .
pnpm --filter @job-assistant/api test:docker
```

可通过 `DOCKER_BIN` 指定 Docker CLI，通过 `API_TEST_IMAGE`、`WEB_TEST_IMAGE` 指定本地镜像标签。测试脚本位于 [docker-smoke.mjs](../../apps/api/tests/docker-smoke.mjs)，只操作随机前缀的临时容器和网络，不读取用户 `.env`，不挂载现有数据库卷，不推送镜像或部署线上服务。

验收项：API 与 Web 生产模式启动、已有数据库迁移、生产邮箱验证和 CORS、两用户隔离、真实资料写入/投影、readiness/analyze/plan、未配置模型时规则路径可用、版本冲突、退出撤销、Web 页面及静态资源、镜像内无本地环境文件。测试完成或失败时清理临时容器、网络与数据库。

### 耗时与缺口

每轮真实请求均为 readiness 1 次、analyze 2 次、plan 10 次，全部 HTTP 200；服务端处理耗时合计分别为 **200 / 139 / 165 ms**，不包含网络及扩展通信耗时。当前规则流程存在按控件选项重建 plan，不是一次 HTTP 请求完成。

首轮阶段耗时：选项/新增探测 23.509 秒，执行 43.906 秒，规划 2.828 秒，结束核验 2.897 秒。慢主要发生在前端交互与探测，不能归因于 AI 或平台 API 服务端处理；规划阶段也不能全部视为服务端耗时。

未修改代码，仅定位了后续问题：

1. [美团页面适配器](../../apps/extension/src/page/adapters/meituan.ts) 的 `probedSections` 仅列教育、语言、工作、项目；校园、荣誉、证书、论文空白区没有进入自动探测，因此 14 项目标未创建。没有资料的竞赛区也触发页面提醒。
2. [后端美团规则](../../apps/api/src/modules/autofill/sites/meituan/parser.ts) 将教育补充信息、工作部门/类型、语言分数标为无等价目录字段；本轮资料虽有 extra 值，规则仍未使用。校园和荣誉的实际标签也与部分现有映射不同，论文缺少字段映射；仅放开新增不足以修复。
3. 英语考试有标准来源但仍未填，需单独复现选项探测/别名匹配后再修复，不能凭当前摘要指定唯一原因。

这些属于既有页面/规则覆盖问题。本轮只做平台迁入验收，保持页面填写逻辑不变，未为提高成绩修改规则或删减目标。
