# 管理员用户管理

页面：`/workspace/admin/users`，仅管理员侧栏显示入口。

## 功能与接口

- `GET /admin/users?q=&role=all&page=1&pageSize=25`：按姓名/邮箱搜索、角色筛选、分页。返回姓名、邮箱、用户 ID、注册时间、邮箱验证状态、角色、航迹总数、已投递数量、网站域名及次数、缺链接数量和最近投递记录更新时间。`pageSize` 支持 10/25/50。
- `PATCH /admin/users/:id/role`：`{"role":"admin","expectedRole":"user"}`，或反向修改。仅允许 `admin/user`，不接受其他用户资料字段；`expectedRole` 防止旧页面覆盖新权限。
- 正式站接口使用 `/api` 前缀、现有 Web Cookie / 插件 Bearer 会话。修改权限必须来自受信任主站 Origin，JSON 请求上限 2KB。普通账号 403、未登录 401，所有响应禁止缓存。

## 数据口径

“已投递”来自现有投递航迹，满足下列任一条件：状态为 `applied/screening/interview/offer`、具有投递日期、存在 `application.submitted` 事件。仅收藏或没有投递证据的已关闭记录不计入。

网站只返回职位链接的规范化 hostname，合并相同域名的记录，隐藏路径、查询参数、片段和 URL 凭据；无有效 HTTP(S) 链接的记录单独计数。此功能不统计全部扩展填写/访问历史，也不读取简历内容、密码散列、会话、邮件或证件资料。

注册时间按数据库 `User.createdAt`，界面使用浏览器本地时区；“最近记录更新”表示已投递记录的 `updatedAt`，不当作最近登录或真实提交时间。

## 权限变更

本接口不允许修改自身角色。在 Serializable 事务内重新检查操作者当前权限和目标角色，保护至少一位管理员；序列化冲突最多重试两次，之后返回 409。目标不存在返回 404，角色已变化返回 409。

只更新 `User.role`；用户资料、技能、经历 ID、会话和投递记录保持不变。现有会话认证每次重新读取用户，所以后续权限检查按新角色执行；已打开的页面可能需刷新以更新导航。权限变更写入 `[admin-audit]` 结构化服务日志，只记录操作者/目标 ID、前后角色和时间。没有新增数据库表或公开管理员初始化接口。

## 验证

2026-10-19：相关测试 214 项通过，生产构建通过。新增用户管理单测覆盖统计口径、隐私字段、分页、输入/来源限制、冲突、角色变更与撤回；本机专用 `*_admin_test` PostgreSQL 库的真实 API 集成覆盖网站聚合、角色即时生效、资料和投递记录保留，以及两个管理员并发互相降级时仍保留一位管理员。

Chrome 通过专用测试库和真实 API 验证搜索、角色筛选、确认弹窗、角色授予/撤回、普通账号禁止访问和自身权限按钮禁用。合成账号测试结束后清理，未修改正式用户角色。原始证据保存在忽略的本地 QA 目录。
