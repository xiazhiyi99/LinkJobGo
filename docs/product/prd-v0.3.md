# 领客产品需求文档（当前版本验收基线）

日期：2026-10-18。产品代码基线：`b26bae5`，功能版本包含 `da6fea2`。

本文根据当前产品页面、接口和已确认需求整理；不把历史架构中的规划能力当成已交付能力。验收环境为 `https://linkaigo.com/autofill-test`，不与生产主站混用。

## 1. 目标与用户

让求职者维护一份结构化简历，在招聘页面复用资料，并集中管理投递进展。

普通用户使用资料、主页、投递航迹和填写；管理员在同等业务权限之外使用扩展诊断与规则维护能力。普通用户不暴露开发入口、密钥或内部日志。

核心流程：注册/网页登录 → 完善资料 → 下载安装扩展 → 打开招聘页 → 点击填写 → 用户自行检查与提交；投递航迹可独立手动使用。填写本身不代表已经投递。

| 模块 | 本版本要求 | 不属于当前交付承诺 |

| 资料 | 基本资料、求职意向、九类经历管理；保存、删除恢复、导出 | 简历排版编辑器 |

## 3. 详细需求与验收标准

### R1 账号与权限

- 邮箱/密码字段校验清晰；密码至少八位，注册需重复密码与邮箱验证码。
- 登录后回到站内目标页面；拒绝站外回跳。未登录不能读取资料和投递数据。
- 会话使用 HttpOnly Cookie；退出后旧会话不可继续使用。扩展通过网站登录复用 Cookie，不要求输入平台账号密码或 Token。
- 普通用户不能自行传入角色升级；管理员能力由服务端返回。账号 A 不能通过记录 ID 访问账号 B 的资料、投递、任务或邮件。
- 邮箱验证码与重置链接不能暴露到生产响应。没有 SMTP/验证码配置时应明确报告环境限制。

### R2 结构化简历

- 基本信息和求职意向可分区编辑、保存、刷新恢复；必填与格式错误有提示。
- 经历包含教育、工作/实习、在校、项目、获奖、论文与专利、语言、证书和技能，可多条保存。
- 删除为软删除并可恢复；取消编辑不写入。扩展始终按当前账号读取，不信任客户端的 userId。
- `GET /profiles/me/autofill-context` 与 `/export` 输出 `resume.autofill.v1`，含稳定 `profileVersion`、标准 `fields`、未知 `extra`、经历 ID/类型/顺序。
- 导出移除数据库内部所有权/时间字段；同样内容的版本稳定，资料改变使版本变化；主页展示内容不进入填写上下文。

### R3 简历导入

- TXT/Markdown 和受支持的 PDF/DOCX 经后端解析；不支持格式、损坏文件和超限文件应有可理解的错误。
- 解析结果先预览，用户选择保留或替换冲突内容，再导入；同一幂等键重试不重复创建经历。
- 模型由统一 AI 网关的环境配置决定，前端和扩展不携带模型密钥；记录真实模型和失败原因。
- 没有模型/OCR 配置时不得把固定示例或空结果当成成功。

### R4 个人主页与头像

- “编辑主页”在当前页编辑显示姓名、城市、签名、描述；保存后刷新保留，取消无副作用。
- 点击头像也能进入编辑；支持 JPG/PNG/WebP，原文件最大 5 MB，浏览器居中裁剪并压缩到最大 512×512 后预览。
- 可替换和移除；只有保存整个信息卡才生效。无图或加载失败显示姓名首字。
- 主页存在 `profile.extra.homepage`，保存时保留其他 extra、求职意向和全部经历；不改变简历标准姓名、标准头像或填写版本。

### R5 投递航迹

- 新增时只要求公司；职位、投递日期及其他字段可空，职位后续可补填或清空。
- 列表按公司组织，支持搜索、状态过滤和分页；空数据、加载及接口错误有反馈。
- 详情显示公司/职位/状态，基本信息、笔试面试、更多信息、任务和历史清楚区分；保存栏可访问。
- 笔试/面试只要求开始时间，不要求结束时间；改期清理不可见的旧结束时间。
- 支持状态流转、版本冲突提示和幂等创建。填写完成事件不得误标记为已投递。
- 跟进任务可新增、完成、重新打开；日历显示相应安排，时间与用户所在时区一致。

### R6 邮件辅助

- 邮箱入口能展示供应商、连接状态、空状态和管理入口；支持配置允许的 IMAP/OAuth 方式。
- 同步展示进展及失败，解析招聘状态并关联记录；账号隔离，重复同步不重复建立业务记录。
- 真实邮箱收信/OAuth/AI 识别依赖配置和可用测试邮箱，不以 mock 成功代替实网验证。

### R7 智能填写网页与扩展

- 教程页包含下载、安装、登录和使用步骤，下载 ZIP 可解压，manifest 与脚本完整、目标 API 前缀一致。
- 已安装扩展能识别网页 Cookie 登录；未登录引导到正确网页登录地址，不存在扩展账号密码输入区。
- 漂浮宠物保持极简，悬停显示填写入口，执行时给出简短进度；详细设置位于扩展弹窗。
- 用户主动点击后，执行资料检查 → 扫描/必要探测 → 按资料对齐经历 → 后端分析/计划 → 页面回填 → 结果反馈。
- 已知页面使用服务端站点规则；未知页面交给统一 AI 网关。URL 负责规则路由，结构指纹仅作规则健康提示，不能因指纹变化就错过可用规则。
- 页面动作只在扩展执行，后端负责解析匹配；新字段绑定当前真实字段 ID。目标经历数来自简历，不由用户在扩展重复设置。
- 覆盖由用户选择；缺资料不编造；不填写其他账号的数据；取消停止后续动作；不会点击招聘页最终投递按钮。
- 普通使用不额外进行独立视觉审核；本次测试的回读和人工视觉核对是验收操作。

### R8 性能与质量度量

- 网站页面渲染和接口请求分别计时；填写总耗时从真实按钮点击到终态，包含扫描、增减和回填，不只报告 AI/接口耗时。
- 报告正确新填、原有正确、错误、未填、无资料及未展开经历，不把扩展“已验证”数直接当独立准确率。
- 准确率 = 正确填写数 / 实际有写入的可判定字段数；召回率/完整度 = 正确覆盖数 / 页面存在且资料可提供的目标字段数。没有可靠分母则报告未完成评分。
- 本轮建立性能基线，不把历史“低于一分钟”写成已通过要求。规则真实填写超过 60 秒列性能问题；60 秒为本轮验收预算，后续可据产品目标调整。

## 4. 数据与接口边界

Web 和扩展仅依赖 API/公共契约；不直接依赖 Prisma 或彼此的页面实现。主页展示和简历输入隔离。资料、投递及邮件数据按服务端身份隔离。模型配置、数据库密码、Cookie 和真实简历不提交仓库，也不出现在测试报告。

当前填写引擎使用 `apps/api/src/modules/autofill/sites` 中的站点解析模块；旧 `/autofill/rules` 表接口是独立管理能力，不能宣称所有当前解析器已从数据库动态加载。

## 5. 发布与验收边界

- 现有功能提交同步 GitHub 和远端隔离测试目录；本轮仅新增 PRD、计划、测试脚本/证据索引与结果，不修产品代码。
- 远端入口完整性也是验收项：API 在源码存在但代理不开放，仍属于该部署的功能阻断。
- 依赖缺失、人工验证码、真实邮箱和第三方网站失效明确标记“阻塞/未测”，不能算通过，也不能误判为已证明的算法错误。
- 不向招聘网站投递、不操作生产真实用户资料、不上传密钥或私人图片。
